# Decode Phase 3C-R — RGB444 p12 packet research

Status: **RESEARCH / STRUCTURAL PROBE ONLY**. This document does not claim a
working RGB444 decoder, pixel parity or production readiness. The production
decoder remains YUV 4:2:2 and unchanged. Issue #2/#12/#13/#14/#16 gates remain
binding.

## Scope

The probe in `tests/reference_formats/rgb444_probe.py` answers one bounded
question: what does an original GoPro CineForm RGB444 p12 sample actually
declare, and can those declarations be validated without the SDK or a private
corpus?

It reads:

- RIFF/AVI `00dc`/`00db` chunks from the frozen
  `upstream/Example/videos/CFHDsample444.AVI` (read-only).
- CFHD sample/group/subband framing from those chunks.
- Tag values, per-channel band geometry and opaque payload hashes.

It does **not** entropy-decode, inverse-transform, reconstruct pixels, link
`upstream/`, invoke the GoPro SDK or touch the production decoder.

## Source-derived contract

All anchors are in the frozen upstream tree.

| Property | Value | Anchor |
| --- | --- | --- |
| Sample type for an intra frame | `9` | `upstream/Codec/decoder.c:2199-2240` |
| Internal encoded format for RGB 4:4:4 | `3` (`ENCODED_FORMAT_RGB_444`) | `upstream/Codec/codec.h:465-489` |
| Public input format observed | `120` (`COLOR_FORMAT_RGB48`) | `upstream/Codec/codec.h` / sample |
| Channels | exactly 3 | `upstream/Codec/codec.h:221` |
| Source precision in the frozen sample | `12` | `CODEC_TAG_PRECISION` (`codec.h:313`) |
| Spatial wavelet orientations | LH=1, HL=2, HH=3 | `upstream/Codec/wavelet.h:312-315` |
| Channel plane order | plane 0 = G, plane 1 = R, plane 2 = B | `upstream/Codec/frame.c:6334-6337`; inverse mapping `upstream/Codec/convert.c:6747-6753` |

The channel order is source-derived. This probe does not verify it by
comparing decoded pixels.

## Band count is derived, not hardcoded

`tests/reference_sample.py` currently requires exactly 30 YUV 4:2:2 subbands.
That is correct for its own corpus but not a general RGB444 rule. The RGB444
probe instead requires:

- one lowpass subband (subband 0) per channel;
- highpass subbands `1 .. num_subbands-1`, each exactly once per channel;
- every highpass declares an orientation in `{LH, HL, HH}`;
- the `(wavelet_level, orientation) -> subband` mapping is identical across
  the three channels;
- each channel declares LH/HL/HH for every wavelet level.

The frozen sample yields 3 × 10 = 30. A synthetic four-level layout with
13 subbands per channel (39 total) is accepted by the same code, so no
30-band assumption is embedded. A future original sample with a different
wavelet/subband count will be parsed structurally if it satisfies these
invariants.

## Running the probe

```bash
python -I tests/reference_formats/test_rgb444_probe.py
```

or, in a standalone CTest configuration:

```bash
ctest --test-dir build -C Release -R rgb444_packet_probe --output-on-failure
```

A caller-provided packet can be inspected without the AVI:

```bash
python -I tests/reference_formats/rgb444_probe.py --packet path/to/rgb444.cfhd --json
```

The JSON contains only geometry, tag values, offsets, payload lengths and
SHA-256 digests. It never embeds payload bytes or machine paths.

The deterministic suite (`test_rgb444_probe.py`, 23 cases) covers the frozen
sample, a synthetic four-level layout and the rejection paths. The committed
output for the frozen sample is
`benchmarks/results/issue17_rgb444_p12_structural_probe.json`, generated by
the command above at probe blob
`8177930cb8aaef1d5c613f90c8bb82ef0ee876ef`. It records all 24 packets, their
framing tags, per-channel lowpass/highpass geometry and every opaque band
payload digest.

## Remaining work and limits

- **F1/F2 differential:** not performed in this run. The private
  `HYPERCINE_GOLDEN_DIR` binding was present but the path was unreachable from
  the automated worktree, so no private packet was read. This is reported as
  `BLOCKED_SHARED_CORPUS_STORAGE` for the differential step, not as a parser
  failure. No private location or filename is published here.
- **No entropy decode:** the highpass payloads remain opaque; only lengths and
  hashes are checked.
- **No pixel parity:** the G/R/B order is source-derived, not decoded.
- **No RGBA4444, Bayer, stereo, interlaced or GOP-2:** those formats have
  different framing and remain separate research paths.
- **No production promotion:** the production path must stay fail-closed for
  these packets until a separate, reviewed decoder milestone exists.
