## Reproduction configuration

Use separate checkouts at the exact heads above. Bind private corpus paths
locally; keep their values out of public logs. Under `HYPERCINE_GOLDEN_DIR`, the
relative Windows root is
`golden/windows/qualities/2026-10-29-issue321-windows-sdk-reference`, and the
separate Linux root is `golden/windows/qualities/2026-10-29-sdk-gaps`.

For #322 configure Visual Studio 2022 x64 with
`HYPERCINE_BUILD_STANDALONE=ON`, `HYPERCINE_BUILD_UPSTREAM=OFF`,
`HYPERCINE_BUILD_BENCHMARKS=OFF`, `HYPERCINE_WINDOWS_SDK_ROOT` bound to the
Windows root, `HYPERCINE_SDK_GAP_CORPUS_ROOT` bound to the separate Linux root,
and `HYPERCINE_SDK_GAP_INDEX_SHA256` set to its digest above.

For #331 configure `HYPERCINE_BUILD_QUALITY_STATE_ONLY=ON`,
`HYPERCINE_BUILD_UPSTREAM=OFF`, `HYPERCINE_BUILD_BENCHMARKS=OFF` and
`HYPERCINE_ISSUE46_GROUP_A_CORPUS` bound to the Windows `group-a-sequences`
directory. Both configurations keep tests enabled and CUDA disabled.

In each checkout run `cmake --build build --config Release --parallel 4`, then
`ctest --test-dir build -C Release --output-on-failure --output-junit results.xml`.
For the historical check use `tools/verify_issue46_group_a.py` at the #331 head
with `--probe` pointing to the historical probe and `--corpus` to Windows A.
Raw JUnit, detailed packet reports and completed CTest logs remain local.
